## 1. 파이썬 개발 환경의 개념 및 필요성

* **개발 환경의 구성 요소를 이해해야 하는 이유**

  * 개발 환경 요소: OS 종류, 하드웨어 스펙, IDE(코드 편집기), 파이썬 버전, 라이브러리 버전, 가상환경 등
  * **환경 불일치 문제**: 개발자 A(Python 2.7)와 개발자 B(Python 3.8)처럼 개발 환경이 다르면 동일한 코드가 정상 작동하지 않거나 의존성 충돌 오류 발생
  * 전역 환경(Global Environment)에 패키지를 계속 설치할 경우 시스템 환경 오염 발생

## 2. 환경 및 패키지 관리 도구

* **pip (Pip Installs Packages)**

  * 파이썬 기본 제공 패키지 관리자
  * `requirements.txt` 파일 기반으로 간단히 패키지 설치 및 관리가 가능하나, 고도화된 가상환경 자동화 및 복잡한 의존성 관리에는 한계

* **Poetry**

  * `pyproject.toml`을 활용한 차세대 의존성 관리 도구
  * 패키지 간 의존성 충돌 자동 해결 및 가상환경 자동 생성 기능 지원

* **uv**

  * Rust 언어로 작성되어 기존 파이썬 관리 도구 대비 **획기적인 속도**를 자랑하는 최신 관리 도구
  * 가상환경 및 파이썬 버전 변경이 용이하고 `pyproject.toml` 지원

* **Docker (도커)**

  * 컨테이너 기술을 사용하여 운영체제(OS) 수준부터 파이썬 환경까지 완전 격리하는 도구
  * OS 차이에 따른 호환성 문제를 완벽히 해결하여 동일한 실행 환경 보장 (단, 가상환경보다 학습 난이도가 높음)

## 3. 파이썬 가상환경 (venv) 실무 가이드

* **가상환경(Virtual Environment)이란?**

  * 프로젝트별로 완전히 독립된 파이썬 실행 환경을 구축하여 패키지 버전 충돌을 방지하는 기술

* **가상환경 주요 CLI 명령어 집합**

  * **파이썬 버전 확인**: `python --version` 또는 `python3 --version`
  * **가상환경 생성**: `python -m venv <가상환경이름>` (예: `python -m venv sprint_venv`)
  * **가상환경 활성화 (Activate)**:

    * *Windows (CMD/PowerShell)*: `call sprint_venv/Scripts/activate`
    * *Mac / Linux / Git Bash*: `source sprint_venv/bin/activate`
  * **가상환경 비활성화 (Deactivate)**: `deactivate`

* **라이브러리 패키지 관리 기법**

  * **명세 파일 기반 통합 설치**: `pip install -r requirements.txt`
  * **현재 활성화된 패키지 목록 조회**: `pip list`
  * **설치된 패키지 명세 동결/저장**: `pip freeze > requirements.txt`

* **개발 툴(VSCode / Jupyter Notebook) 커널 등록**

  * **VSCode**: `F1` (Mac: `Cmd + Shift + P`) $\rightarrow$ `Python: Select Interpreter` 선택 $\rightarrow$ 생성한 가상환경 내 `python.exe` 경로 지정
  * **Jupyter Notebook (.ipynb)**: 상단 우측 `Select Kernel` $\rightarrow$ `Python Environments...` $\rightarrow$ 해당 가상환경 선택
