## 1. 가상화의 개념 및 역사

* **가상화의 개념**
  * 컴퓨터의 물리적 하드웨어를 효율적으로 활용하기 위해 리소스를 추상화하는 기술
  * 운영체제나 애플리케이션을 하나의 물리적 시스템에서 독립적으로 실행되도록 처리
  * 하나의 실물 컴퓨팅 자원을 여러 가상 환경으로 분할 및 운영 (하이퍼바이저 활용)

* **가상화 기술 비교**
  * **전통적인 시스템 (Traditional System)**: 물리 서버에 OS를 직접 설치하여 소프트웨어 실행, 자원 미분리로 효율성이 낮고 환경/버전 충돌 위험 존재
  * **가상 머신 (Virtual Machine)**: 하이퍼바이저 기반으로 독립된 OS를 각각 생성. 부팅 시간이 길고 GB 단위 용량으로 구동 시 Host 컴퓨터 부하 발생
  * **컨테이너 (Container)**: Linux 환경 기반, MB 단위 용량 및 빠른 초기화 시간 제공. Host OS 및 소프트웨어를 공유하여 가볍고 독립된 실행 환경 구동

* **가상화 발전 역사**
  * **2013년**: Docker 오픈소스 공개
  * **2014년**: Google Kubernetes 프로젝트 발표 및 Docker 1.0 정식 릴리즈
  * **2015년**: Kubernetes 1.0 정식 릴리즈
  * **2020년대**: Kubernetes 기반 컨테이너 오케스트레이션이 업계 표준으로 정착

## 2. 도커의 개념

* **도커의 등장**
  * **2013년 3월**: DotCloud(솔로몬 하익스 설립)에서 개발 후 오픈소스 출시
  * **2014년 6월**: Docker 1.0 정식 출시
  * **목적**: 서버 간 환경 차이로 인한 종속성 문제 해결 및 자원 할당/반납 관리를 지원하는 도구

* **도커 컨테이너 (Docker Container)**
  * 애플리케이션, 코드, 라이브러리, 환경 설정 파일, 데이터베이스 등을 포함한 가벼운 독립 실행 환경
  * 공유 주방처럼 기본 설비가 갖춰진 상태에서 필요한 식재료만 추가하여 실행하는 구조

* **컨테이너 도입 효과**
  * 기기 및 환경에 구애받지 않는 동일한 개발 환경 제공
  * 서비스 리소스의 확장성 및 유연성 보장
  * 단일 물리 서버 내 복수 서비스 독립 배포 지원

## 3. 도커의 활용

* **핵심 구성 요소**
  * **도커 이미지 (Docker Image)**: 코드, 라이브러리, 런타임 환경 등 컨테이너 실행에 필요한 제반 요소를 담은 템플릿
  * **도커 파일 (Dockerfile)**: 베이스 이미지 및 환경 설정 단계를 순차적으로 정의한 이미지 생성용 파일
  * **도커 허브 (Docker Hub)**: 도커 이미지를 저장하고 배포하는 중앙 레지스트리 (공개 및 프라이빗 저장소 지원)

* **도커 워크플로우 (Workflow)**
  * `Dockerfile 작성` $\rightarrow$ `Docker Image 빌드` $\rightarrow$ `Docker Hub Push` $\rightarrow$ `다른 서버에서 Pull` $\rightarrow$ `Container 생성 및 실행`

* **도커 주요 활용 사례**
  * 팀 간 서로 다른 환경에서의 프로그램 실행 및 협업 필요 시
  * 확장 가능한 애플리케이션 배포 및 마이크로서비스 아키텍처(MSA) 구축 시
  * 호스트 서버 환경 변화(OS 업그레이드, 데이터 이행 등)에 대응 필요 시

* **도커의 한계 및 주의사항**
  * 리눅스용 소프트웨어 중심으로 지원
  * 호스트 서버 장애 발생 시 내부 모든 컨테이너에 영향을 미침
  * 단일 소규모 서비스의 장기 운용 시 도입 이점이 상대적으로 적음
  * 네트워크 및 스토리지 관리의 복잡성 존재
