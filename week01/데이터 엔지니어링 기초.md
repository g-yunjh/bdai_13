## 1. 데이터 엔지니어링의 개념 및 핵심 용어

* **데이터 엔지니어링 (Data Engineering)**

  * 대규모 데이터를 효율적으로 수집, 저장, 처리, 변환 및 전송할 수 있는 **인프라와 파이프라인 시스템 구축 작업**

* **데이터 저장소 체계**

  * **Data Lake (데이터 레이크)**: 정형, 반정형, 비정형 등 다양한 형태의 대용량 원천 데이터를 가공 없이 원형 그대로 저장하는 시스템
  * **Data Warehouse (DW / 데이터 웨어하우스)**: 기업 전체의 의사결정을 지원하기 위해 정형화 및 표준화된 데이터를 중앙에서 통합 관리하는 저장소
  * **Data Mart (DM / 데이터 마트)**: 특정 부서나 비즈니스 목적(예: 마케팅, 재무)에 맞추어 데이터 웨어하우스에서 일부 데이터를 추출·가공한 소규모 저장소

* **데이터 거버넌스 및 메타데이터**

  * **Data Governance (데이터 거버넌스)**: 데이터의 보안, 품질, 관리 권한, 표준화 정책 및 수명주기를 관리하는 조직 차원의 관리 체계
  * **Data vs Metadata**:

    * *Data*: 데이터의 실체 및 분석 대상 (예: 실제 텍스트, 사진 파일, 튜플 값)
    * *Metadata*: 데이터의 속성, 생성일자, 작성자, 스키마 구조 등 "데이터를 설명해 주는 데이터"

* **처리 방식 및 인프라 구조**

  * **Batch Processing (배치 처리)**: 일정 주기(매시, 매일, 매월 등)마다 대량의 데이터를 한 번에 일괄 처리하는 방식
  * **Streaming Processing (스트리밍 처리)**: 데이터 발생 즉시(초 단위 이하) 실시간으로 연속 처리하는 방식
  * **On-Premise vs Cloud**: 자체 물리적 서버/데이터센터를 보유하는 방식(On-Premise) vs AWS, GCP 등 원격 데이터센터 인프라를 사용하는 방식(Cloud)

* **파이프라인 및 데이터 변환 기법**

  * **Data Pipeline (데이터 파이프라인)**: 원천 데이터 수집부터 정제, 변환, 분석, 저장, 최종 전달까지 데이터의 안전한 이동 프로세스 전반
  * **ETL (Extract, Transform, Load)**: 원천 데이터 수집(Extract) 후 먼저 정제/변환(Transform)하여 DW에 적재(Load)하는 방식 (고품질 정형 데이터 관리 및 보고서 작성에 용이)
  * **ELT (Extract, Load, Transform)**: 원천 데이터 수집(Extract) 후 우선 저장소/레이크에 적재(Load)한 뒤 필요에 따라 변환(Transform)하는 방식 (빅데이터/클라우드 환경에 최적화)
  * **OLTP vs OLAP**:

    * *OLTP (Online Transaction Processing)*: CRUD 중심의 실시간 트랜잭션 처리 최적화 (데이터 무결성 강조, 백엔드 DB용)
    * *OLAP (Online Analytical Processing)*: 대규모 조회를 통한 대량 분석 및 복잡한 SELECT 쿼리 최적화 (의사결정 및 대시보드용)

* **데이터 포맷 및 최적화 기법**

  * **Row-oriented (행 지향)**: CSV, JSON 등 행 단위 저장. 트랜잭션 추가/수정에는 유리하나 대용량 분석 시 속도가 저하됨
  * **Column-oriented (열 지향)**: Parquet, ORC 등 열 단위 저장. 필요한 컬럼만 선택하여 읽으므로 조회/분석 속도가 매우 빠르고 압축률이 높음
  * **Parquet (파케이)**: 뛰어난 파일 압축률(CSV 대비 최대 80% 감소), 컬럼 기반 고속 조회, 스키마/타입 저장 기능, Spark 및 빅데이터 시스템 친화적 포맷
  * **Partitioning (파티셔닝)**: 대용량 데이터셋을 특정 기준(예: creation_date)으로 디렉터리/파일별로 분할 저장하여 Scan 범위를 줄이고 쿼리 성능을 대폭 개선하는 기법

## 2. 데이터 엔지니어의 R&R (Role & Responsibilities)

* **핵심 역할 및 가치관**

  * 데이터 인프라와 파이프라인 설계, 구축, 운영 및 유지보수
  * 원천 데이터의 불완전성 해결: **GIGO (Garbage In, Garbage Out)** 환경에서 **Garbage In, Data Out**으로 고품질 데이터 가공

* **직군별 비교 (DE vs DA vs DS)**

  * **데이터 엔지니어 (Data Engineer)**:

    * *역할*: 파이프라인, ETL, DW 구축, 데이터 안정성 및 품질 관리
    * *기술 스택*: SQL, Python, Airflow, Spark, Kafka, Docker, Cloud 등
  * **데이터 분석가 (Data Analyst)**:

    * *역할*: 데이터를 통한 비즈니스 인사이트 도출, 성과 분석 및 리포트 작성
    * *기술 스택*: SQL, Excel, Tableau, Power BI, Python 등
  * **데이터 과학자 (Data Scientist)**:

    * *역할*: 고급 통계 분석 및 비즈니스 문제 해결을 위한 머신러닝/딥러닝 예측 모델링
    * *기술 스택*: Python, R, TensorFlow, PyTorch, SQL 등

## 3. 대표적인 데이터 엔지니어링 워크플로우 예시

1. **대용량 분석 및 시각화 워크플로우**: MongoDB(비정형 저장) $\rightarrow$ Apache Spark(정형 데이터 변환) $\rightarrow$ RDBMS(MySQL) $\rightarrow$ Power BI / Tableau 시각화
2. **데이터 아카이빙 워크플로우**: Monthly Batch 수행 $\rightarrow$ PostgreSQL의 데이터 처리 $\rightarrow$ 5년 미만 데이터는 아카이빙 저장, 5년 이상 데이터는 자동 삭제
3. **웹 API ETL 수집 워크플로우**: Hourly Batch 수행 $\rightarrow$ Web API 수집 및 Pandas 정제 $\rightarrow$ GCS, Amazon S3, Google BigQuery에 분산 저장
4. **실시간 추천 시스템 워크플로우**: 쇼핑몰 사용자 행동 데이터 발생 $\rightarrow$ Apache Flink(실시간 스트림 전처리) $\rightarrow$ Redis(인메모리 저장소) $\rightarrow$ AI 추천 모델 연동
5. **실시간 모니터링 시스템 워크플로우**: 거래 데이터 발생 $\rightarrow$ RabbitMQ(메시지 브로커 수집) $\rightarrow$ Spark Streaming(대용량 처리) $\rightarrow$ ElasticSearch(실시간 검색/분석) $\rightarrow$ 모니터링 알림
